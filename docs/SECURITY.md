# امنیت

## داده‌های خارج از کد منبع

این مخزن نباید شامل توکن ربات، رمز پنل، کلید API درگاه، شمارهٔ کارت، دامنه یا شناسهٔ
عدددار مدیر باشد. این اطلاعات از دو محل خوانده می‌شوند:

1. فایل `.env`: توکن ربات، مدیران، مسیرها، نام نمایشی و نام کاربری پشتیبانی؛
2. جدول `settings` در پایگاه داده: کلید پنل PasarGuard، تنظیمات درگاه و شمارهٔ کارت.

اگر از مخزن انشعاب می‌گیرید، فایل `.env` خود را بسازید و هرگز آن را ثبت نکنید.

## چک‌فهرست پیش از انتشار یا استقرار

- [ ] فایل `.env` واقعی در Git ثبت نشده است؛ خروجی `git ls-files | grep -i env` فقط باید
  `.env.example` را نشان دهد.
- [ ] پایگاه داده، نسخهٔ پشتیبان و گزارش‌ها در Git ثبت نشده‌اند.
- [ ] توکن ربات جدید است؛ توکن افشاشده باید باطل و جایگزین شود.
- [ ] کلید API پنل PasarGuard فقط روی سرور مورد اعتماد نگه‌داری می‌شود.
- [ ] `PANEL_ADMINS` فقط شامل شناسه‌های عددی مورد اعتماد است.
- [ ] `PANEL_PRIMARY_OWNER_ID` شناسهٔ مالک اصلیِ قفل‌شده است و با `.env` هم‌خوانی دارد.
- [ ] روی سرور، مجوز فایل‌های حساس محدود شده است: `chmod 600 .env` و `chmod 600 sibil.sqlite3`.

## سخت‌سازی پیشنهادی سرور

```nginx
location ~ ^/(logs|backups|uploads)/ { deny all; }
location ~ \.sqlite3$             { deny all; }
location ~ /\.                    { deny all; }
location ~ ^/uploads/.*\.php$     { deny all; }
```

- سرویس ربات را با یک کاربر غیر `root` مانند `sibil` اجرا کنید.
- در دیوار آتش فقط پورت‌های 22، 80 و 443 را باز بگذارید و دسترسی به پورت پنل
  PasarGuard را به نشانی‌های IP مورد اعتماد محدود کنید.

## کنترل‌های امنیتی در کد

- همهٔ کوئری‌ها از Prepared Statement در `DB::one/all/exec/update` استفاده می‌کنند.
- تغییرهای حساس مانند پرداخت، موجودی، شمارش واریزی و پاداش با CAS
  (`UPDATE … WHERE col=?`) در برابر اجرای تکراری محافظت می‌شوند.
- وب‌هوک درگاه‌ها با امضا یا هش اعتبارسنجی می‌شوند و مبلغ ورودی با مبلغ سفارش تطبیق داده می‌شود.
  ثبت موفقیت فقط پس از `confirm` و `verify` انجام می‌گیرد.
- تصویرهای احراز هویت روی دیسک ذخیره نمی‌شوند و فقط `file_id` Telegram نگه‌داری می‌شود.
- پیام‌های خطای کاربر مسیرهای داخلی یا جزئیات پایگاه داده را افشا نمی‌کنند.

## گزارش آسیب‌پذیری

آسیب‌پذیری یا ایراد امنیتی را به‌صورت خصوصی گزارش کنید تا پیش از انتشار عمومی بررسی و
اصلاح شود.
